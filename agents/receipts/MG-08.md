## What changed

- **`crates/caim/Cargo.toml`** - one new dependency, `ctrlc = { version = "3.5.2", features = ["termination"] }`.
  Licence MIT / Apache-2.0, so it is inside the MG-07 `deny.toml` allow list. `termination` is what makes
  the handler see SIGTERM and SIGHUP as well as SIGINT; on Windows the same handler covers Ctrl+C,
  Ctrl+Break, a console close and logoff. `Cargo.lock` gains 7 packages: ctrlc 3.5.2, nix 0.31.3 and
  cfg_aliases 0.2.2 (Unix), block2 0.6.2, dispatch2 0.3.1, objc2 0.6.5, objc2-encode 4.1.0 (Apple). On
  Windows ctrlc uses `windows-sys` 0.61.2, which the tree already had, so nothing new is added there.
- **`crates/caim/src/server.rs`** - `StopHandle` (`crates/caim/src/server.rs:261`) and
  `Server::stop_handle()` (`crates/caim/src/server.rs:232`). `StopHandle::press()`
  (`crates/caim/src/server.rs:271`) is the shutdown path: the first press sets the stop flag and calls
  `Runner::request_stop()`, which is exactly what Enter does today; a press after that returns true,
  meaning "leave now", and `forced()` remembers it. `Server::shutdown()` is unchanged, so the endpoint
  file still goes away only when it holds this start's token (`endpoint::remove` asks `is_ours` first).
- **`crates/caim/src/main.rs`** - `watch_signals()` (`crates/caim/src/main.rs:179`) installs
  `ctrlc::set_handler`: the first press calls `press()`, a second press calls
  `std::process::exit(EXIT_FAILED)` from the signal thread, which is exit code 1. If the handler cannot
  be installed the server still runs, prints the sentence, and stops on Enter as before. The terminal
  line now reads "press Enter or Ctrl+C to stop cleanly. A second Ctrl+C leaves at once."
- **`README.md`** - "Stopping it" rewritten: Enter and Ctrl+C are the same clean stop; a second Ctrl+C
  ends at once with exit code 1 and may leave the file behind.
- **`agents/guards.txt`** - one new line, `MG-08 | craft-ai-manager | cargo test`.

## Tests

No real signal is sent in any test; both call the function the handler calls.

- `server::tests::one_press_cancels_the_running_and_queued_jobs_and_a_second_press_says_leave_now`
  (`crates/caim/src/server.rs:727`): a fake backend with a 40 ms step, one job inside the backend and
  one queued. `press()` returns false, the stop flag goes up, and once the worker has joined both jobs
  are `Cancelled`. The next two presses return true and `forced()` is true.
- `server::tests::the_signal_stop_removes_the_endpoint_file_and_survives_being_called_twice`
  (`crates/caim/src/server.rs:752`): a real `Server` with an endpoint file. `press()` then
  `shutdown()` removes the file; a second `press()` returns true, and `shutdown()` again is `Ok` with
  the file still gone - so a Ctrl+C that lands after the file is already away cannot fail the stop or
  leave the file behind.

## Manual check on Windows (the prompt asked for it)

`target/agent-mg-08/debug/caim.exe serve --fake-backend`, with Ctrl+C delivered by
`GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)` from a helper that attaches to the child's console and
ignores the event itself (`E:\CraftML\work\.codex-tmp\mg08-ctrlc-check.ps1`, local only), so the real
exit code is readable. `endpoint.json` is the default `%LOCALAPPDATA%\CraftAI\endpoint.json`.

| presses | gap | exit code | `endpoint.json` after |
|---|---|---|---|
| 1 | - | 0 | gone |
| 2 | 0 ms | 1 | still there - the forced exit beat the cleanup |
| 2 | 30 ms | 0 | gone - the clean stop had already finished |
| 2 | 250 ms | 0 | gone |

One Ctrl+C is the clean stop with exit 0. A second one that arrives while that stop is still running
leaves at once with 1, and the stale file is the same harmless case the README already describes: a
client gets a refused connection, and the next start replaces it.

## Known gaps and follow-ups

- On Windows a **console close** (the X button, logoff, or shutdown) gives the process a few seconds and
  then terminates it whatever happens. `ctrlc` releases its semaphore and returns TRUE, so the clean
  stop starts, but it is not guaranteed to finish inside the grace period. Ctrl+C and Ctrl+Break are not
  time-limited, and those are the cases the prompt asked about.
- A second Ctrl+C can leave `endpoint.json` behind (row 2 above). Deliberate: the user asked to leave,
  and the stale file is the documented case.
- The MG-01 receipt's "No Ctrl+C handler" gap is closed by this task; `agents/receipts/MG-01.md` is left
  as written, since it records what was true then.
