## Review round 1 (Codex, on `c4fc0c0`)

Codex-cloud reviewed `c4fc0c0` and found three things: one P1 and two P2. All three are in the two new files; nothing else moved.

- **P1 - `preprocess_to` let its caller choose the allocation** (`crates/caim/src/birefnet.rs:87`). `3 * plane_size` was unchecked, so a big `size` wrapped the length in a checked build and asked for an enormous allocation in an optimised one. New `MAX_PREPROCESS_SIDE = 2048` bounds the public size (the model wants 1024, so the headroom is real but finite), and every length - the source plane, one channel's plane, the packed NCHW output - is worked out with `checked_mul` before anything is allocated. Outside the bound the function answers empty; the runner's own call uses `MODEL_SIZE`, which is inside it.
- **P2 - a shrinking axis aliased** (`crates/caim/src/birefnet.rs:135`). `axis_weights` took the two samples around the destination centre whatever the direction, which is right for enlargement and wrong for reduction - and reduction is not hypothetical, because the mask task's 1,048,576-pixel cap admits a 4096x256 image, so a 4096-wide axis really does come down to 1024. `axis_weights` now widens the tent to the reduction factor, which is what PIL `BILINEAR` does and what the preprocessing contract in `agents/models/birefnet.md` records. `axis_weights_two_tap` and `resize_two_tap` keep the narrow rule for `matte`: the committed mattes came from a Python run that used two taps on the way back (`tests/fixtures/SOURCE.md`), and the golden test is the check against that run, so the resize it measures has to stay the one that made the fixture.
- **P2 - no model folder meant no tasks** (`crates/caim/src/routing.rs:84`). `Offered::from_store` answered an empty `Offered` when neither a named root nor a platform data directory exists, so `GET /v1/tasks` listed nothing and a client could not tell "not installed" from "not a feature". `Offered::from_root` takes the folder as an argument and builds the catalog with a readiness predicate that is always false; `from_store` is now a one-line call to it. A job for `subject_mask` on such a machine gets amendment 18's not-ready sentence rather than the unknown-task one.

Re-run gates on the round-1 commits: `cargo fmt --check` 0, `cargo clippy --workspace --all-targets -- -D warnings` 0, `cargo test --workspace` **267 passed / 0 failed / 4 ignored** - four new tests: the widened tent (1:3:3:1 over an interior 8 -> 4 shrink), the narrow one, a single bright sample spread over two destination pixels instead of landing on one, and the bounded public size. `cargo test --test golden -- --ignored --nocapture` **3 passed** with the same numbers as before the fix (buoy IoU 0.9997 / 1885 soft-edge pixels, person IoU 0.9996 / 6919, warm-run drift 0 levels, LaMa unchanged): both fixtures are smaller than 1024 on every axis, so their preprocessing is enlargement only and the bytes that reached the model did not change. `Cargo.toml` and `Cargo.lock` are still untouched, so the `deny` result stands.

## Known gaps and follow-ups

- **No device choice yet.** `device_requested` is always `auto` and `device_name` always `"CPU"`: no CUDA execution provider is compiled in, and `backends` says `cuda`/`coreml` are `untested`. #4812 found this graph's logits collapse on the DirectML EP, which is why nothing is marked supported but cpu. MG-11's resolver and CAIM-04's setting are where that changes; `fallback_reason` already carries the amendment 18 vocabulary.
- **`memory_mib` is reported, not enforced.** Amendment 18's memory check belongs to MG-11. LaMa's 1500 MiB is a **stated guess** (208 MB of weights plus one 512x512 crop's activations), not a measurement; BiRefNet's 6600 is RS-01's measurement.
- **Mask size refusal.** Amendment 18 says a mask task is never refused for the size of the *document*, because PhotoCraft downscales first. CAIM still caps the size that is actually sent at the entry's `max_pixels` (1,048,576 for `subject_mask`), so a client that ignores the downscale cannot outrun the memory budget; `protocol::tests::the_mask_task_is_capped_by_its_own_entry` pins it. Fill's 413 over 64 MP is unchanged.
- **The connection test flake** above: worth a small task of its own if it recurs.
- **`subject_mask` has no `--fake-backend` parity test for PhotoCraft's own shapes beyond the ellipse**; the fake mask is deterministic and cancels, which is what UP-02/PC-09 need.
- The mask goldens need both models installed, so they stay `#[ignore]`d; CI does not run them. The `MG-10` guard line is `cargo test`, which counts them as ignored.
