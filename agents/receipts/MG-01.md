## Behaviour rules covered

SPEC v1.1 amendment 11 (the wire contract), each end to end over real TCP against a started server:

- Token on every request, constant-time compare: `a_request_without_the_token_is_refused` (no token and a wrong token both 401), plus the `token::bearer_matches` unit tests.
- DNS-rebinding guard: `a_host_that_is_not_our_loopback_port_is_refused` (400 before any route is looked at).
- Happy path - health, tasks, submit, poll, result, result.png, same size, depth and channels, unmasked pixels identical: `the_happy_path_fills_the_masked_area`; 16-bit RGBA keeps its shape: `a_sixteen_bit_rgba_image_comes_back_in_the_same_shape`.
- Bad multipart, parts out of order, and `job.json` disagreeing with the image or mask: `a_body_that_is_not_the_three_parts_is_refused`, `a_part_that_disagrees_with_the_job_is_refused` (400 with a plain sentence).
- Unknown job 404, result before done 409, body over the cap 413 (refused before the body is read), ninth queued job 503: `a_job_this_manager_does_not_know_is_404`, `a_result_that_is_not_ready_yet_is_409`, `a_body_over_the_cap_is_refused_before_it_is_read`, `the_ninth_queued_job_is_told_the_manager_is_busy`.
- Cancel while queued and while running, FIFO order: `a_queued_job_is_cancelled_before_it_starts`, `a_running_job_is_cancelled_between_its_steps`, `two_jobs_finish_in_the_order_they_arrived`.
- Endpoint file: `the_endpoint_file_names_the_port_and_token_that_work`, `the_file_is_replaced_on_the_next_start`, `a_file_another_run_owns_is_left_alone`, `a_start_that_cannot_write_its_file_does_not_start`; `CRAFT_AI_ENDPOINT` override; atomic temp + rename in `endpoint::write`.
- Malformed request line, header over 8 KiB, missing `Content-Length` on POST: `a_broken_request_gets_a_400_and_the_server_keeps_serving`.
- No backend installed: `without_the_fake_backend_there_is_nothing_to_run` (also checked live, table above).

SPEC v1.1 amendment 14 (provenance): `/result` carries `model`, `device`, `provider`, `elapsed_ms` and `image_size`. `the_happy_path_fills_the_masked_area` asserts the fake backend's `fake-fill` / `cpu` / `local`, and the manual PhotoCraft run below shows the engine passing them through into its own result JSON (PhotoCraft FEATURES B08, already ticked by PC-04).

Never-crash rules (PhotoCraft `AGENTS.md` §3, CAIM `AGENTS.md`): `#![forbid(unsafe_code)]` plus the six no-panic clippy lints at the top of `lib.rs` and `main.rs`; `clippy.toml` allows unwrap / expect / panic / indexing in tests only; `cargo clippy --all-targets -- -D warnings` is the gate and is clean. ## Known gaps and follow-ups

- **No Ctrl+C handler.** `std` has no signal handling and MG-01 adds no dependency for it, so on Windows Ctrl+C ends the process where it stands and leaves `endpoint.json` behind. When stdin is a terminal, Enter stops cleanly instead - that is what both live runs above did - and a stale file is harmless: a client sees a refused connection, and the next start replaces it. The README says so. A real handler needs a crate (for example `ctrlc`), which is Erik's call.
- A result's PNG is freed once it has been read, which is amendment 11's "10 minutes or until read, whichever is first". A client that loses the body has to resubmit rather than retry. Worth revisiting if PhotoCraft ever needs that retry.
- `rust-version = "1.95"` is declared but not tested: CI builds `stable` (1.99 on this PC). An MSRV job belongs in CI now that there is code that could drift.
- CI now has `Swatinem/rust-cache@6323deb102c322ba6fcbdcafc7e3dddab59af2b6` (v2.9.2), pinned to a full SHA and verified by cloning the tag and reading its `action.yml` - MG-00's follow-up. The first CI run will show whether the cache pays for itself.
- Jobs live in memory only: a restart forgets queued and finished jobs. MG-05's staged runner may want them on disk.
- The fake backend's `elapsed_ms` is usually 0 because a 40x30 fill takes under a millisecond; the number is measured, not a placeholder.
- `/v1/tasks` lists `fill_masked_area` only with `--fake-backend`. Real models are MG-02 (store and manifest) and MG-04 (ONNX runner); MG-05 adds the staged job runner.
- PhotoCraft's `agents/FEATURES.md` row CAIM-01 ("loopback server with a token, `endpoint.json`, job API") is the row MG-01 implements. It is still `todo`: the MG-01 prompt limits the PhotoCraft change to the one `agents/TASKS.md` line, so ticking CAIM-01 is left to the review.
- The 16-bit image path is covered by a test; a 16-bit *mask* is refused on purpose, because amendment 11 fixes the mask at 8-bit grayscale.
