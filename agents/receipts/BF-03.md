## Policy choices to review

- Default image-data reservation budget: **2 GiB**, adjustable through `ServeOptions::memory_limit`.
- Working-space estimate: **128 bytes per pixel + 32 MiB**. This is deliberately conservative, not a
  process-RAM guarantee. ORT session allocations, allocator overhead, and kernel socket buffers are
  excluded. The advertised 64 MP ceiling is unchanged; an image below it may receive 503 due to the
  budget. A smaller image or consuming retained results can free capacity. CLI budget configuration
  is not added in this change.
- Retained records and pending worker IDs: **1,024 each**. Existing ten-minute retention stays intact;
  new work gets 503 at the limit rather than evicting results early.
- Whole response deadline: **30 seconds**, configurable through `ServeOptions::write_timeout`.
- Result consumption remains one-shot on a successful server-side write. This repairs *detected*
  failures without changing the protocol. A disconnect after the kernel accepted every byte is not
  detectable as missing receipt; guaranteed delivery would require a separate acknowledgement.
- CPU preparation, PNG encoding, and model loading remain cooperative: shutdown waits for a current
  non-interruptible stage boundary. ORT inference uses its existing termination path.
