## What changed

Six source files, `README.md`, one guard line. 340 insertions, 21 deletions.

- `store::folder_usage(path) -> Option<Usage>` with `Usage { bytes, files }`: walks a folder on a stack, never follows a link, adds with `saturating_add`, and is `None` when the path is missing or is not a folder.
- `endpoint::published_port(path) -> Option<u16>`: the port an endpoint file names, `None` when the file is missing, unreadable, not JSON, or the port is not a `u16`. `is_ours` now reads through the same `read_value` helper.
- `models::list_lines`: each model line ends with `on disk: <bytes> bytes` (0 when its folder is missing), an empty catalog prints `The model catalog has no entries.`, and the last line is always `total on disk: <bytes> bytes in <files> files, models folder <root>`.
- `models::remove_model(model, root, endpoint, probe)`: first `live_server_port` - an endpoint file whose port answers on loopback within 250 ms - and refuses with the port in the sentence; then deletes `<models folder>\<id>\<version>\` whole (model file, `verified.json`, `acknowledged.json`, any `.part` and `.lock`), says how many files and bytes went, and drops `<id>` as well when that was its last version (`remove_dir` only succeeds on an empty folder, which is the check). Asks no questions. A stale endpoint file whose port answers to nobody does not block the removal.
- `installed_folder` is the safety belt: it refuses unless `catalog::is_name(id)` and `catalog::is_name(version)` both hold and the folder sits under the models folder as exactly `<id>\<version>`. `catalog::is_name` is now `pub(crate)`.
- `models::where_line(root, from_env)`: `models folder: <path> (from CRAFT_AI_MODELS)`, or `(the default data folder)` when nothing named it.
- `cli.rs` / `main.rs`: `models remove <id>`, `models where`, the usage block, the two `--help` lines, and the "needs a models command: list, install, verify, remove or where" sentence. Exit codes: 0 removed, 2 the arguments, 3 unknown model / nothing installed / a manager is answering.

## Known gaps and follow-ups

- No `--yes` and no undo, as the prompt says. The catalog has to name the id, so the only way to delete the wrong thing is to name a model that is really installed.
- "Is a manager using it" is answered by the endpoint file plus a loopback connect, not by a lock the server holds. A third process listening on that port blocks the removal, and a manager that died without cleaning up does not. A per-model lock is the CAIM-05 / CAIM-11 follow-up.
- `models remove <id>` resolves an id through `models::find`, so two versions of one id is a question rather than a silent choice; version choice belongs with CAIM-02.
- The MG-09 guard line is the same `cargo test` as the other six CAIM lines, so it proves the suite ran under that name rather than adding coverage of its own.
- `folder_usage` counts every file in the model folder, so a half-finished `.part` shows up in `models list` - deliberate, that is the disk use CAIM-05 is asking about.
- The PhotoCraft `agents/TASKS.md` row for MG-09 (branch `ai/mg-09-status`) is not in this PR: PR #17 is changing that same file, so the row comes after it merges.
