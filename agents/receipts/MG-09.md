## Review round 2: what the re-reviews found, and what round 3 changed

The re-review of `be5be8ef` found the test-setup bug as a P1 of its own - the link target built inside
the store instead of outside it - which is the failure the ubuntu job had already reported and the
second commit had already fixed. The re-review of `813d63ca` then found one more, a **P2: the disk-use
walk follows a link it was handed** (`crates/caim/src/store.rs:211`). `folder_usage` opened the folder
with `std::fs::metadata`, which follows a link, and `read_dir` follows it too; checking
`DirEntry::file_type` only stops links met *after* the walk begins. So with a symlink or Windows
junction at `<models>\<id>`, `models list` walked the tree on the other side of the link and printed
its bytes, while the doc comment promised that a link is never followed.

Round 3 fixes it:

- `store::is_link` asks `symlink_metadata` whether a path is a link rather than the folder itself -
  `Path::is_dir` follows the link and answers about the folder on the other side, which is what made
  the callers' `None if folder.is_dir()` branch able to lie.
- `folder_usage` reads the folder it was handed with `symlink_metadata`, so a link there is `None`
  rather than a walk through it, and the doc comment now says which of the three answers is which.
- `models::linked_step` names the first link in `<models folder>/<id>/<version>`, counting the models
  folder itself, and both callers use it: `installed_folder` (the removal sentence is unchanged) and
  `list_lines`, which prints `on disk: a link, not a folder` for that model and
  `total on disk: a link, not a folder` for the total, rather than a count taken through a link.
- Three tests come with it, all `#[cfg(unix)]` so the ubuntu job runs them:
  `store::tests::folder_usage_refuses_a_link_handed_in_as_the_folder`,
  `models::tests::list_refuses_to_count_a_model_folder_that_is_a_link`, and
  `models::tests::list_refuses_to_count_a_models_folder_that_is_a_link`.
- Proven on this Windows box as well (`E:\CraftML\work\.codex-tmp\mg09\smoke-link-r3.txt`): a plain
  store still counts (`on disk: 1200 bytes`, `total on disk: 1200 bytes in 1 files`); a junction at
  `<store>\lama` prints `on disk: a link, not a folder` and `total on disk: 0 bytes in 0 files`; a
  junction at the models folder prints `a link, not a folder` in both places; and `models remove`
  still refuses with the link named in both shapes, with the bytes behind the junction still on disk.

**The CI failure was ours.** Both CAIM jobs stopped at `Format`: the round-3 patch rewrote the test

**The P1 is a bypass of the round-3 link guard.** Codex-cloud, reviewing `f9a25a7` at
`crates/caim/src/store.rs:209`: `CRAFT_AI_MODELS=/somewhere/models/` names the same folder spelled
with a trailing separator, and on Unix a trailing separator asks the filesystem for a directory, so
`symlink_metadata` answers about the folder a link called `models` points at rather than about the
link. `is_link` then says "not a link", `linked_step` misses the root, `models list` counts the tree on
the far side, and `models remove` can reach `remove_dir_all` through that same link - the round-1 fix
undone by one character.

- `store::without_trailing_separators` rebuilds the path from `Path::components`, which drops a
  trailing separator and folds doubled separators and `.` steps while leaving a root (`/`, `C:\`) and
  an empty path exactly as they are. `is_link` and the start of `folder_usage` both ask about that
  shape, and `models_dir_in` normalises the folder the environment names, so every path built from it
  is clean and `models where` prints one spelling rather than two.
- Two tests come with it. `folder_usage_refuses_a_link_handed_in_as_the_folder` now asks about the same
  link spelled with a trailing separator as well, and the new
  `a_models_folder_named_with_a_trailing_separator_is_still_checked_for_a_link` refuses both the count
  and the removal through it. Both are `#[cfg(unix)]`; the `models_dir_in` assertion added to
  `the_models_folder_follows_the_environment_then_the_data_dir` is cross-platform and runs here.
- Checked here as far as Windows lets it: `models where` prints the folder without the separator, a
  junction at `<store>\lama` and a junction at the models folder both still refuse the count and the
  removal when the folder is spelled with a trailing separator, and the bytes behind each junction
